RIYA(Coordinator)ORGANISER LINK
Starts the trip, then calls the round.
  • Opens Together and creates a trip
  • Later: taps Generate options once the board reads n / n ready
  • Taps Lock group choice when the group has voted
Three fields, nothing more.
  • Trip name (80 chars max)
  • Her own name
  • Currency as a 3-letter code, e.g. INR
  • On lock: the winning option id
Holds the only organiser key.
  • Private fragment link #organizer=…, never sent to the server in a URL
  • Sees live submit progress and who is still WAITING
  • Sees earlier rounds and what each one locked
Server checks her role, not her word.
  • POST /api/trips mints a slug plus an organiser token
  • Token is SHA-256 hashed and matched against organizer_token_hash
  • Blocked if fewer than 2 members or anyone has not submitted
One link that opens the whole thing.
  • Public group link /trip/<slug> to share
  • Her own private edit link
  • A ready round, or a conflict with reasons
  • The locked group choice, kept in history
FRIENDS(x 4, or any number)MEMBER LINK
The shared link lands in the chat.
  • Opens /trip/<slug> and joins by name
  • Returns via their private link to edit an answer
  • Votes when a round goes ready
One short form each.
  • Origin airport code, e.g. DEL
  • Earliest departure, latest return
  • Budget per person
  • Destination style: beach, city, nature, adventure, culture, or open
  • Excluded destinations, likes, dealbreakers
Private answers, public progress.
  • Private fragment link #member=… is the only way back in
  • Form reloads prefilled with their saved answer
  • Everyone sees names, READY or WAITING, options and vote totals
Validated before anything is stored.
  • join rejects a duplicate name in the group
  • submit enforces a real IATA code, a real date range and a budget above zero
  • vote upserts on (round, member), so a vote can change until lock
Their place in every option.
  • Preferences saved, plus their private edit link
  • Per-option position: preferred style, different style, over budget, excluded or price unavailable
  • Their own cost against their own budget
TRIP PLANNER
APP(Next.js 16 on Vercel)SERVER ROUTES
Every request to the trip route.
  • GET /api/trips/[slug] on each page load
  • POST with one action: join, submit, generate, vote, lock
  • Round work runs up to 60s of server time
Action plus proof of identity.
  • JSON body with the action and its payload
  • x-member-token header carrying the secret from the link fragment
  • Stored rows for the trip, its members, rounds, options and votes
The whole group state, per request.
  • Shared date window: latest start against earliest end, at least one night
  • Hard limits: budgets, excluded destinations, date range
  • Staleness: has anyone joined or edited since this round
Where the group maths happens.
  • Hash the token to resolve member and organiser role
  • Score each candidate per person: 100 preferred style, 65 different style, 0 if blocked, over budget or unpriced
  • Rank by group fit, break ties on total cost, keep the top 3
  • Tally votes; refuse voting or locking on a stale round
One JSON state the page renders.
  • Ready round: up to 3 options with fit %, costs and per-person positions
  • Conflict round: a plain list of what stopped it
  • Member roster, vote tally, previous rounds
  • No fake prices, ever
GEMINI(LLM)3.5 FLASH-LITE, FREE TIER
Called once per round.
  • Only after the organiser starts a round
  • Only if the group has a shared window of at least one night
  • Skipped entirely on a date conflict
The group, summarised.
  • Shared start and end date
  • Per member: origin, budget, style, likes, dealbreakers, exclusions
  • Explicit instruction to avoid every exclusion and dealbreaker
Boxed in by a schema.
  • responseMimeType: application/json with a required JSON schema
  • Type must be one of the five styles; reason under 140 chars
  • 20s timeout, no caching
  • Told to return no prices
Suggests, never decides.
  • Proposes 3 distinct real destinations with valid city IATA codes
  • Writes one short reason per destination
  • App discards anything failing the ^[A-Z]{3}$ code check
Candidates only.
  • { city, country, iata, type, reason } x 3
  • Feeds price checking and scoring, which it has no say in
  • A model error surfaces as a readable message, not a blank screen
SUPABASE(Database)POSTGREST, SERVER ONLY
Every read and write in the flow.
  • Trip creation, join, submit, round, vote, lock
  • Page load reads the current state
Five tables.
  • trips, members, rounds, options, votes
  • Hashed tokens only, never the secret itself
  • Quotes and per-person positions stored as JSON
Closed by default.
  • RLS on every table; anon and authenticated revoked
  • Reached only from the server with a secret key
  • Unique (trip, name); cascade deletes from the trip down
Persist and retrieve.
  • Insert trip, member and round rows; patch a member on submit
  • Vote upsert keyed on (round, member): one live vote each
  • Options returned ordered by score, then cost
The group state that survives.
  • Anyone can reopen the link days later and see the same thing
  • Every earlier round and its locked choice stays readable
  • A new round never overwrites the last one
SERPAPI(Google Flights + Hotels)IN USE, NOT OPTIONAL
Once per candidate destination.
  • Runs inside a round, right after Gemini answers
  • Candidates checked two at a time to stay inside the free plan
Real search parameters.
  • Hotels: city, check-in and check-out, group size, trip currency
  • Flights: one round-trip search per distinct origin to the candidate IATA
A free plan with real limits.
  • 250 searches a month: 1 hotel + 1 flight per origin, per destination
  • 20s timeout per call
  • 401 and 429 are turned into plain instructions, not stack traces
Cheapest verified offer wins.
  • Lowest total hotel rate for the whole stay
  • Cheapest round-trip fare per origin; same-city origin costs zero
  • Any missing leg voids the candidate rather than guessing
A quote, or an honest gap.
  • Flight price per member, hotel name and total, quote timestamp
  • Compare links back to Google Flights and Hotels
  • Or: "no complete flight and hotel prices for <city>", shown as a round issue
Budget rule: one round-trip fare per person plus an equal share of the quoted hotel total, checked against that person's own budget. Enforced in code, not by the model: shared dates, per-person budget and excluded destinations. Free-text dealbreakers only shape what Gemini suggests, so the group should still read them before booking.
